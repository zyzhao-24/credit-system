# 团校积分系统 - 使用指南

本文面向部署与运维本系统的管理员，介绍安装、初始配置、日常运维与常见问题。

## 一、快速开始

### 1. 安装依赖

后端依赖使用 [uv](https://docs.astral.sh/uv/) 管理（`pyproject.toml` + `uv.lock`），一条命令即可安装全部依赖并自动创建 `.venv`：

```bash
uv sync
```

前端为 React SPA，生产部署需要先构建：

```bash
cd frontend
npm install
npm run build
cd ..
```

### 2. 配置环境变量

```bash
cp .env.example .env
```

编辑 `.env`：

| 变量 | 说明 |
| --- | --- |
| `SECRET_KEY` | 至少 32 字节的随机字符串，**生产环境必须设置**（缺省时拒绝启动）。同时用于派生 OTP 密钥与 SMTP 密码的加密密钥，更换后所有已绑定 OTP 失效、SMTP 密码需在维护页重新录入 |
| `DATABASE_URL` | 默认为 `sqlite:///instance/credit_system.db`，一般无需修改 |
| `JWT_EXPIRES_SECONDS` | 登录令牌有效期，默认 43200（12 小时） |
| `CORS_ORIGINS` | 开发期放行 Vite dev server（默认 `http://localhost:5173`）；生产同源部署可留空 |

数据库为 SQLite，**首次启动时自动创建于 `instance/` 目录，无需任何手动初始化**。

### 3. 启动系统

**开发环境**（Flask 开发服务器，仅监听 127.0.0.1，端口 5000）：

```bash
uv run python run.py
```

**生产环境**（Waitress / cheroot，通过 `.env` 加载配置）：

```bash
# Windows
start_server.bat        # 启动
status.bat              # 查看状态
logs.bat                # 查看日志
stop_server.bat         # 停止
cleanup.bat             # 停服并清理 server.pid / server.log

# Linux
./start_server.sh
./status.sh
./logs.sh
./stop_server.sh
./cleanup.sh
```

启动脚本会自动检查并安装依赖、从 `.env` 加载环境变量、校验 `SECRET_KEY`，并通过 `server.pid` 与 `server.log` 管理进程与日志。`cleanup` 脚本只停止本项目记录的进程，不影响机器上其他 Python 程序。

### 4. 访问系统

- 学生登录：`http://localhost:5000/login`
- 管理员登录：`http://localhost:5000/admin/login`（固定路径）

生产模式（`start_server.bat` / `start_server.sh`）启动后会自动启用 HTTPS，地址变为 `https://localhost:5000/...`。

## 二、初始管理员设置（本机维护页）

系统内置唯一的系统管理员账号 `system`，首次启动时自动创建，初始密码为不落盘、不打印的随机值（无人知晓）。因此**首次启动后必须先在服务器本机完成初始化**：

1. 在服务器本机用浏览器打开 `http://localhost:5000/local/system`；
2. 在“账号安全”页签中**重置 system 密码**：自定义新密码（至少 8 位），或留空由系统随机生成强密码——新密码只在结果页显示一次，请立即妥善保存；
3. 点击“生成新的 OTP 二维码”，用验证器应用（Microsoft / Google Authenticator 或微信验证器小程序）扫码，并**输入 6 位验证码确认后 OTP 才生效**（中途放弃则不变）。

维护页的安全限制：

- 仅来自服务器本机（127.0.0.1 / ::1）的请求可见，非本机访问一律返回 404；
- 表单带短时签名令牌并校验跨站请求头，防止其他网站代为提交。

> 注意：system 密码、system OTP、邮件服务配置**只出现在本机维护页**，Web 管理后台不提供这些入口。

## 三、登录与两步验证

登录强制“密码 + TOTP 动态验证码”两步验证：

1. 输入账号密码；
2. 打开验证器应用，输入 6 位动态验证码，完成登录。

各角色的 OTP 绑定方式：

- **system**：在本机维护页 `/local/system` 扫码绑定；
- **普通管理员**：创建账号时接口一次性返回二维码与 Base32 密钥（仅本次可见），需当场绑定；未绑定 OTP 的管理员无法登录，由 system 管理员在后台“重置 OTP”生成二维码转交；
- **学生**：注册需先通过学号邮箱验证码验证；注册成功后立即弹窗绑定 OTP，可跳过（按未绑定处理）；忘记密码同样走“邮箱验证码 + 自设新密码”，成功后可选重绑 OTP。若学生的 OTP 被管理员重置，其下次登录时密码验证通过后会自动收到含新二维码的邮件，完成重新绑定。

## 四、邮箱配置

注册验证码、OTP 二维码、忘记密码等邮件均由“服务邮箱”发送，配置**只能在服务器本机访问** `http://localhost:5000/local/system` 的“邮件服务”页签完成：

1. **服务邮箱**：发件用邮箱地址；
2. **密码/授权码**：SMTP 授权码（见下方说明），留空保持不变；已保存的授权码明文仅该页面可见；
3. **学生邮箱后缀**：用于学号邮箱验证码（如 `@example.edu.cn`，系统按“学号 + 后缀”拼出收件地址）；
4. 保存后建议点击“发送测试邮件”验证连通性，失败时页面会附调试信息。

### 常用邮箱的授权码获取

系统按服务邮箱域名自动匹配 SMTP 服务器（QQ / 163 / 126 / Gmail / Outlook / 其他自动检测）：

- **QQ 邮箱**（`smtp.qq.com`）：登录网页版邮箱 → 设置 → 账号 → 开启“POP3/IMAP/SMTP”服务，按短信验证获取 16 位授权码；
- **163 / 126 邮箱**：设置 → POP3/SMTP/IMAP → 开启 SMTP 服务并获取授权码；
- **Outlook 个人邮箱已禁用 SMTP**，建议使用 QQ 或 163 邮箱。

> 授权码不是邮箱登录密码。更换 `SECRET_KEY` 后已保存的授权码无法解密，需在本机维护页重新录入。

## 五、批量操作格式

### 1. 批量导入学生（CSV 文本）

在管理后台“学生管理”中使用批量导入，每行一个学生的 CSV 文本：

```
学号,姓名[,初始密码]
```

- 学号只能包含数字，姓名为必填；
- 第三列初始密码为可选：新学生未提供时使用默认密码 `123456`；**已存在的学生不会被静默重置密码**，只有显式提供第三列时才更新其密码；
- 已存在的学号会更新姓名（并按上述规则决定是否更新密码），其余为新增；
- 逐行校验，格式错误的行会被列入结果中的错误列表，不影响其余行导入。

### 2. 批量学分录入

在活动管理中选择活动与记录后批量录入学分，每行一条的文本格式：

```
学号或姓名[,学分]
```

- 第一列为纯数字时按学号匹配；否则按姓名匹配（同名学生全部写入）；
- 第二列学分为可选，缺省时使用表单中设置的默认学分；学分列格式错误会在结果中报告；
- 已存在该学生的记录则更新学分与类别，否则新增记录条目；
- 所有条目继承表单中选定的学分类别。

## 六、HTTPS 说明

`deploy_server.py`（由 `start_server` 脚本调用）启动前会自动生成自签名证书（`instance/tls.crt` / `instance/tls.key`，SAN 含 localhost 与本机内网 IP），并以 cheroot 提供 HTTPS（端口不变，默认 5000）；仅当证书生成失败时才回退明文 HTTP。

- 自签名证书不受浏览器信任，访问时提示“不安全”属预期，点击“高级 → 继续前往”即可（Firefox 可永久记住例外）；
- 内网 IP 变化或证书到期时重签：`uv run python gen_cert.py --force`，随后重启服务；
- 如需彻底消除警告，可用域名 + Let's Encrypt 等受信证书；
- 生产部署务必通过 HTTPS 访问：浏览器发送的是密码的 SHA-256 摘要与 JWT，明文 HTTP 下可能被嗅探重放；
- 若部署在同机反向代理之后，务必在代理层拦截 `/local/system` 路径，否则所有请求的来源地址都会变成回环地址，维护页的“仅本机访问”限制会失效。

## 七、常见问题

**端口 5000 被占用？**

先查找占用进程（`netstat -ano | findstr :5000`），停止占用进程后重试，或通过环境变量 `PORT` 指定其他端口；开发服务器默认仅监听 127.0.0.1，请确认访问的是本机地址。

**忘记 system 密码 / OTP 失效？**

在服务器本机访问 `http://localhost:5000/local/system`：重置密码（自定义或随机生成），并重新生成 OTP 二维码扫码确认即可。该页面不依赖登录状态，是本机恢复 system 账号的唯一通道。

**其他管理员无法登录？**

未绑定 OTP 的管理员无法登录。由 system 管理员在后台为其“重置 OTP”，生成二维码后转交本人扫码绑定。

**邮件发送失败？**

在本机维护页用“发送测试邮件”排查：确认使用 SMTP 授权码而非登录密码；确认域名对应的 SMTP 服务已开启；查看结果页的调试信息。更换过 `SECRET_KEY` 后需重新录入授权码。

**证书警告？**

属预期行为，见上文 HTTPS 说明；`uv run python gen_cert.py --force` 可重签证书。

**如何完全重置运行状态？**

`cleanup.bat` / `cleanup.sh` 停止本项目进程并删除 `server.pid` 与 `server.log`；数据库与证书位于 `instance/` 目录，如需彻底清空可停止服务后删除该目录（再次启动会自动重建空库）。

# 问卷系统完整功能说明

> 面向管理员与开发者。本文以当前代码为准（后端 `backend/`、前端 `frontend/`），
> 描述问卷系统的概念模型、生命周期、报名规则、签到机制与 API。

## 0. 背景与范围

- 认证采用 **JWT（HS256，12 小时）+ TOTP 两步验证**（密码验证后凭 `otp_ticket`
  换取正式令牌），本文不再展开。
- **旧"注册问卷"已移除**：手机号、微信号、建议直接存放在 `students` 表
  （`phone` / `wechat` / `suggestion` / `info_updated_at`），不再是独立问卷实体。
  学生在"报名信息"页（`/student/profile`）自行维护，管理员在"学生管理"中查看/编辑/导出。
  旧 `registration_questionnaires` 表在启动时删除，历史数据不保留。
- 本文聚焦两类问卷：
  - **活动问卷**：绑定某个活动（`activity_id` 非空），通常同时绑定该活动的
    一条记录（`record_id`），用于活动报名与意向类别收集。
  - **独立问卷**：`activity_id` 为空，不绑定任何活动，仅限系统管理员创建与管理。

## 1. 概念与数据模型

### 1.1 问卷模板 `activity_questionnaires`

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `questionnaire_id` | String(36) PK | UUID |
| `activity_id` | String(36)，默认 `""` | 绑定活动；空字符串 = 独立问卷。**故意不设外键**（旧行为：活动删除后模板保留） |
| `record_id` | String(36)，默认 `""` | 绑定的记录，必须属于 `activity_id` 对应的活动；空 = 未绑定。意向类别题由记录类别自动生成 |
| `title` | String(200) | 问卷标题 |
| `start_time` / `end_time` | DateTime | 报名起止时间，开始必须早于结束 |
| `max_participants` | Integer，默认 0 | 最大报名人数，0 = 不限 |
| `has_category_question` | Boolean | 由绑定记录类别自动推导：记录有 ≥2 个类别时为真 |
| `custom_questions` | JSON 数组 | 自定义题目定义（见第 3 节） |
| `body` | JSON，可空 | 正文文档：段落数组，每段是 `text` / `question` / `field` 片段的有序混排；`NULL` 为旧数据，读取时按题目顺序合成 |
| `version` | Integer，默认 1 | 模板版本：标题、题目、正文或绑定记录每次修改时 +1；提交记录绑定提交时的版本 |
| `checkin_open` | Boolean | 现场签到会话开关（每人独立一次性签到码，见第 5 节） |
| `checkin_code` | String(16) | **已废弃**：早期全问卷共享签到码，现仅留作历史兼容 |
| `created_time` | DateTime | 创建时间 |
| `status` | `active` / `closed` | 生命周期状态 |

约束与索引：

- 部分唯一索引：**同一活动同时只能有一个 `active` 状态的问卷**
  （`activity_id != ''` 时；独立问卷不受此限）。
- `status` 取值受 CHECK 约束限制。

### 1.2 报名/填写记录 `questionnaire_responses`

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `response_pk` | Integer PK | 自增主键（排名同分时的次序依据） |
| `response_id` | String(36)，唯一 | 对外 UUID |
| `questionnaire_id` | FK → 模板，级联删除 | 所属问卷 |
| `student_id` | String(32)，**无外键** | 提交快照可独立于学生行存在 |
| `student_name` / `phone` / `wechat` | String | 提交时从学生档案快照复制 |
| `intended_category` | String(100) | 意向学分类别（见 2.3） |
| `custom_answers` | JSON | 自定义题目答案：`{question_id: {answer: string \| string[]}}` |
| `template_snapshot` | JSON，可空 | 提交时的问卷快照（标题/类别题开关/自定义题目/正文），模板后续修改不影响历史提交 |
| `template_version` | Integer，可空 | 提交时模板版本（旧数据为 NULL） |
| `submit_time` | DateTime | 提交时间，排名依据 |
| `status` | `active` / `cancelled` | 报名状态；取消后重报复用同一行并刷新 `submit_time` |
| `checked_in_at` / `checkin_confirmed` | DateTime / Boolean | 签到时间与确认标记 |
| `absent` | Boolean | 缺席标记：不占用名额，候补自动转正 |
| `checkin_code` | String(16) | 每人独立的一次性签到码；开启签到时分配，签到成功或关闭签到后清空 |

约束：`(questionnaire_id, student_id)` 唯一 —— 每生每问卷仅一条记录。

### 1.3 与活动表的同步

活动问卷创建/修改/删除后，系统把"最近创建的 active 模板"的
`questionnaire_start` / `questionnaire_end` / `max_participants` / `has_questionnaire`
同步回 `activities` 表，供活动列表展示"问卷报名：n/m 人"。

## 2. 问卷生命周期与报名规则

### 2.1 状态与时间窗

- 模板状态：`active`（可报名）→ `closed`（管理员手动关闭）；也可直接删除
  （删除后其全部填写记录因级联一并删除）。
- 可报名条件：`status == active` 且 `start_time ≤ now ≤ end_time`。
  未开始 / 已截止 / 已关闭分别返回明确错误。
- 截止时间后，已提交的报名按最终排名显示"成功/失败"；模板仍可被编辑。

### 2.2 提交与校验流程（`POST /api/student/questionnaire/submit`）

1. 学生必须已在"报名信息"页填写**手机号和微信号**，否则拒绝提交。
2. 时间窗与状态校验（见 2.1）。
3. 意向类别解析（见 2.3）。
4. 自定义答案按题目定义校验（必填、选项合法性、数值范围、日期格式、
   评分范围、文本长度与格式，见第 3、4 节）。
5. 唯一性：已存在 `active` 记录则报"您已报名此问卷"（数据库唯一约束兜底）。
6. 保存问卷快照与版本号；若之前取消过（存在 `cancelled` 记录），**复用该行**
   并更新联系方式、答案、快照与 `submit_time`。
7. 签到开启期间的新报名（含取消后重报）：名额内自动补发一次性签到码；
   候补默认不发码。

### 2.3 意向学分类别

由绑定记录的类别集合自动决定，**不是管理员手加的题目**：

- 未绑定记录 / 独立问卷：无类别概念，存空串。
- 记录只有一个类别：无需提问，自动归入该类别。
- 记录有多个类别：自动生成单选的类别槽位，答案必须是候选类别之一；
  学生缺省作答记为 **"无"**。

管理端可在事后修改某条记录的意向类别，但仍限于记录的可行类别（多类别时允许"无"）。

### 2.4 名额、排名与候补（`backend/services/ranking.py`）

- 排名只统计 `status == active` 且 **未被标记缺席** 的记录，按
  `submit_time` 升序、`response_pk` 升序（同秒提交的先后）编号，从 1 开始。
- `max_participants == 0`：不限名额，所有 active 报名均为"成功"。
- `max_participants > 0`：`rank ≤ max_participants` 为**成功**，超出部分为**候补**。
  **超额提交不会被拒绝**，而是进入候补名单。
- **取消**：`status → cancelled`，立即让出名次，后续候补按顺序自动前进。
- **取消后重报**：复用原记录并刷新 `submit_time`，名次重新排到当前末尾。
- **修改报名**（`PUT .../update/<response_id>`）：只改答案与意向类别，
  **不改变 `submit_time`，因此不影响名次**；已取消的报名不能修改。
- **缺席标记**（管理员）：`absent = true` 的记录不参与排名、不占名额，
  候补自动转正；取消缺席标记后恢复占名额。

### 2.5 学生可见的状态

- 进行中：成功 / 候补（显示 `rank/max_participants` 或报名顺序）。
- 已截止：成功 / 失败（未入选）。
- 已取消的记录保留在"我的报名"中供查看。

## 3. 自定义题目

题型定义见 `backend/services/questionnaires.py` 的 `QUESTION_TYPES` 与
`frontend/src/lib/questions.ts`。设计器可插入 6 种题型；`description`（说明文字）
与 `textarea` 仅存在于旧数据（说明文字由正文文本段落承担，`textarea` 等同
`text + multiline`）。

每道题的公共字段：`question_id`（客户端可指定，缺省服务端生成）、`order`、
`question_text`（必填，用于校验提示与导出列名）、`required`（必填开关）。

| 题型 | 类型值 | 可配置项 | 答案校验 |
| --- | --- | --- | --- |
| 单选题 | `single_choice` | 选项列表（≥2、去重、去空白）；`allow_other` 允许"其他"自定义项 | 答案必须是选项之一；开启"其他"时接受 `其他：xxx` 形式的自由填写 |
| 多选题 | `multiple_choice` | 同上 | 答案为数组，每项须合法（"其他"规则同上） |
| 文本题 | `text` | `multiline`（多行作答/简答）；`max_length`（1–5000，默认单行 200、多行 500）；`format` 格式校验 | 超长拒绝；格式预设：`none`（无）/ `phone`（`^1[3-9]\d{9}$`）/ `email` / `idcard`（18 位）/ `regex`（自定义正则，保存时已校验合法性） |
| 数字题 | `number` | `min_value` / `max_value`（可空 = 不限，最小不得大于最大） | 必须是数字且在范围内 |
| 日期题 | `date` | — | 必须是 `YYYY-MM-DD` |
| 评分题 | `rating` | `max_rating`（2–10，默认 5） | 必须是 1..max_rating 的整数 |

保存模板时服务端执行 `normalize_custom_questions` 统一规范化（生成缺失 ID、
重排 `order`、按题型补默认值）；前端 `validateQuestions` 先行给出同样的校验提示。

## 4. 正文文档（文字 + 槽位混排）

问卷正文是一篇**可直接打字编辑的文档**（设计器支持 Markdown 与 `$...$` 公式，
渲染用 remark/rehype-katex）：

- 段落数组，每段是三类片段的有序混排：
  - `{"type":"text","text":...}` 文字；
  - `{"type":"question","question_id":...}` 题目槽位 —— 每道可作答题目
    **必须恰好放入正文一次**（前后端均强制），删除题目时槽位同步移除；
  - `{"type":"field","field":...}` 信息槽位 —— 可重复使用，提交时自动取
    学生档案与问卷绑定信息：`student_name` 姓名、`student_id` 学号、
    `phone` 手机号、`wechat` 微信号、`activity_name` 活动名称、
    `record_name` 记录名称、`category` 意向类别（多类别记录时是学生的文内单选）。
- 学生填写后，槽位替换为作答/取值，未作答显示空缺符号，整篇即为连贯文档
  （`frontend/src/lib/letter.ts` 的 `composeLetter`）。
- 旧模板 `body` 为 `NULL` 时按题目顺序自动合成（说明文字变文本段，
  其余题目各占一段），前后端逻辑一致（`synthesize_body` / `synthesizeBody`）。
- 选择"其他"的答案存储与展示均带 `其他：` 前缀（防伪造固定选项），
  渲染时剥除前缀；评分答案渲染为 `X 分`。

## 5. 现场签到（一次性签到码）

管理员在问卷详情页开关"现场签到"。规则：

- **开启签到**（`POST /api/admin/questionnaire/<id>/checkin/open`）：
  为每位名额内（成功）且未签到的 active 报名者分配**独立的 6 位数字一次性码**
  （问卷内唯一）；候补默认不分配，需要时在记录行逐人"生成"。
- **关闭签到**：作废全部未使用的码；已签到记录不受影响。
- **学生签到**（`POST /api/student/questionnaire/<id>/checkin`）：
  输入本人 6 位码，或扫管理员出示的二维码（链接
  `/student/activities?checkin=<问卷ID>&code=<码>` 自动带入）。码必须与本人
  报名对应的码一致（每人一码，他人代输无效）；签到成功后**码立即作废**；
  被标记缺席者不能签到。
- **签到状态机**（`checkin_state`）：
  - `absent` 缺席（不占名额）；
  - `none` 未签到；
  - `pending` 待确认 —— 已签到但既不在名额内又未确认（如候补签到），
    管理员"确认签到"后生效，或候补因前面有人缺席/取消转正后自动变为有效；
  - `valid` 已签到（在名额内或已确认）。
  注意：当前学生签到接口在码校验通过后直接置为已确认（即时生效），
  `pending` 分支保留给"已签到未确认且不在名额内"的记录。
- **管理端签到操作**（均在问卷详情页的记录行）：
  - 确认签到（待确认 → 生效；未签到的可直接"标记签到"代签，无需签到码）；
  - 取消签到（恢复未签到；签到仍开启时自动补发新码；取消后才能标记缺席）；
  - 逐人生成签到码（候补适用）；
  - 标记/取消缺席（缺席不占名额，候补自动转正；已签到须先取消签到）。
- **签到码仅管理端可见**：学生端接口不下发签到码字段，防止远程代签；
  管理端可出示逐人二维码供本人扫码。

## 6. 管理端能力

入口：`/admin/questionnaires`（模板卡片列表，可按标题/活动搜索），
`/admin/questionnaires/design`（设计器），`/admin/questionnaires/design/<id>`（编辑）。

- **权限**：绑定活动的问卷，拥有该活动编辑权限的管理员即可管理；
  独立问卷仅系统管理员可创建/查看/管理。模板列表中系统管理员看全部，
  普通管理员只看自己可编辑活动绑定的问卷。
- **创建模板**：选活动（系统管理员可选"无"= 独立问卷）→ 选绑定记录
  （选活动必须选记录，记录须属于该活动）→ 标题、起止时间、人数上限 →
  正文与题目。同一活动已有 active 问卷时拒绝创建。
- **编辑模板**：改标题/时间/人数/题目/正文/绑定记录；内容（标题、题目、
  正文、绑定记录）变化时版本号 +1；只改时间不升版本。历史提交按快照展示。
- **关闭 / 删除**：关闭即 `status=closed`（学生不可再报，历史保留）；
  删除连同全部填写记录一起删除。
- **查看填写记录**：排名、学号、姓名、联系方式、意向类别、提交时间、
  提交时版本、状态（成功/候补/已取消/截止后成功或失败）、签到状态；
  详情弹窗按**提交时的快照**渲染题目答案，并合成正文文档预览；
  可搜索学号/姓名/联系方式；可编辑记录的联系方式与意向类别；可删除单条记录。
- **导出**：
  - 单问卷导出 xlsx（`{标题}_填写记录.xlsx`）：列 = 排名、学号、姓名、
    手机号、微信号、意向学分类别、提交时间、状态、问卷版本、签到、签到时间，
    其后每道题目一列。题目列取**当前模板与所有历史快照题目的并集**
    （按题目 ID 去重、保持顺序，说明文字不导出），多选答案以 `、` 连接；
    已取消记录排在最后。
  - 全部问卷汇总导出（仅系统管理员，`questionnaires_YYYYMMDD_HHMMSS.xlsx`）：
    类型、学号、姓名、手机号、微信号、备注（活动/标题/状态/意向类别）、提交时间。

## 7. API 端点概览

统一约定：除标注外均需相应角色 JWT；返回
`{"success": bool, "message": str, ...}`。

### 学生端（`backend/api/questionnaires.py`）

| 方法与路径 | 说明 |
| --- | --- |
| `GET /api/student/questionnaires/available` | 时间窗内可报名问卷（含我的报名状态、名次、是否候补、类别、题目与正文） |
| `GET /api/student/questionnaires/my_registrations` | 我的全部报名（含状态、排名、签到状态与签到开关） |
| `POST /api/student/questionnaire/submit` | 提交/重报（`questionnaire_id`、`intended_category`、`custom_answers`） |
| `PUT /api/student/questionnaire/update/<response_id>` | 修改 active 报名的答案与意向类别（不改名次） |
| `POST /api/student/questionnaire/cancel/<response_id>` | 取消报名 |
| `POST /api/student/questionnaire/<questionnaire_id>/checkin` | 现场签到（body：`{"code": "6位码"}`） |

### 管理端（`backend/api/admin_questionnaires.py`）

| 方法与路径 | 说明 |
| --- | --- |
| `GET /api/admin/questionnaires/all` | 模板列表（按权限过滤，按创建时间倒序） |
| `POST /api/admin/questionnaire/create_template` | 创建模板（活动问卷或独立问卷） |
| `PUT /api/admin/questionnaire/template/<id>` | 编辑模板（内容变化时版本 +1） |
| `DELETE /api/admin/questionnaire/template/<id>`（及等价的 `DELETE /api/admin/questionnaire/<id>`） | 删除模板（级联删除填写记录） |
| `PUT /api/admin/questionnaire/update` | 修改模板状态（`active`/`closed`） |
| `GET /api/admin/questionnaire/responses/<id>` | 填写记录列表（含每人签到码，仅管理端） |
| `GET /api/admin/questionnaire/responses/<id>/export` | 导出该问卷 xlsx |
| `PUT /api/admin/questionnaire/response/<response_id>` | 修改记录联系方式/意向类别 |
| `DELETE /api/admin/questionnaire/response/<response_id>` | 删除单条记录 |
| `POST /api/admin/questionnaire/<id>/checkin/open` / `.../close` | 开启/关闭签到（开：分配名额内签到码） |
| `POST /api/admin/questionnaire/response/<rid>/checkin/confirm` | 确认签到 / 直接代签 |
| `POST /api/admin/questionnaire/response/<rid>/checkin/code` | 逐人生成签到码 |
| `POST /api/admin/questionnaire/response/<rid>/checkin/cancel` | 取消签到（开启中补发新码） |
| `POST /api/admin/questionnaire/response/<rid>/absent` | 标记/取消缺席（body：`{"absent": true/false}`） |
| `GET /api/admin/questionnaires/export` | 全部问卷汇总导出 xlsx（仅系统管理员） |
